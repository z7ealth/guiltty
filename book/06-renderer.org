#+TITLE: The renderer: from cells to pixels
#+STARTUP: overview

* Two halves: core and backend

#+begin_example
  c_src/renderer/
  |-- core/                    knows SDL, FreeType, the protocol; no GPU API
  |   |-- main.c               the port, the window, events, the cell mirror
  |   |-- protocol.c/.h        framing and safe message reading
  |   |-- atlas.c/.h           fontconfig + FreeType -> a glyph bitmap
  |   `-- backend.h            the interface every backend implements
  `-- gl/                      knows OpenGL; nothing about ports or fonts
      |-- gl_backend.c
      `-- shaders/cell.vert, cell.frag
#+end_example

The core never includes a GL header. It calls the backend through a struct
of function pointers ([[file:../c_src/renderer/core/backend.h][backend.h]]):

| Field          | When it's called                                      |
|----------------+-------------------------------------------------------|
| =window_flags= | read before creating the window (=SDL_WINDOW_OPENGL=) |
| =configure=    | before the window exists: ask SDL for GL 3.3 core     |
| =init=         | after the window exists: context, shaders, buffers    |
| =upload_atlas= | once: the glyph bitmap becomes a texture              |
| =draw_frame=   | whenever something changed: draw and present          |
| =resize=       | when the drawable size changes                        |
| =shutdown=     | on exit                                               |

=gl_backend.c= defines =renderer_backend=, and the Makefile links core +
gl into =guiltty_gl=. The Vulkan side quest adds =vk/= and a second
binary, =guiltty_vk=, without touching the core.

* The glyph atlas

A GPU can't draw a font; it draws textures. So the core keeps one picture,
the *atlas*, holding every glyph currently in use, cut into cell-sized
slots; each cell then just names its slot.

1. fontconfig resolves ="monospace"= to a file (here Source Code Pro).
2. FreeType opens it at 18 px (times the screen's scale) and measures one
   *cell*: the advance width of =M= by ascender + descender (11 x 23 px).
3. Glyphs are drawn into slots the first time a cell shows them.

#+begin_example
   RGBA, 2048 px wide: 186 slots per row of 11 x 23 px
  +---+---+---+---+---+---+---+---+---+-------+---+---
  |   | h | é | l | o | $ | 日| ─ | ✓ |  😀   | a | ...     slot 0 is blank
  +---+---+---+---+---+---+---+---+---+-------+---+---
                                     a wide glyph: two slots
#+end_example

Glyphs share a *baseline*: FreeType reports how far each glyph's bitmap
reaches above it (=bitmap_top=), and the baseline sits =ascender= pixels
below the top of the cell. All atlas sizes go through =ckd_mul= (checked
multiplication), so a silly font size can't overflow.

Until MVP 5 this was an 8-bit bitmap of ASCII 32..126, built once at
startup. How glyphs from other fonts get in, emoji included, and how the
atlas fills and empties is [[file:14-fonts-and-atlas.org][the fonts chapter]].

* Two draw calls for the whole screen

The OpenGL backend draws every cell (1920 for 80 x 24) with
=glDrawArraysInstanced=: 4 vertices (a quad, as a triangle strip) times one
*instance* per cell. It does it twice: backgrounds first, then glyphs
blended on top (see [[file:08-colors.org][the colors chapter]] for why).

Each instance reads its cell, a =struct cell= of 12 bytes, as vertex
attributes:

#+begin_example
  struct cell { slot, attrs, fg[3], bg[3], pad[2] }  ->  a_slot  a_attrs  a_fg  a_bg
              (glyph found and colors resolved by the core)  uint   uint    vec3  vec3

  CPU (each frame)                        GPU
  cells: 1920 x 12 bytes            --->  per-instance attributes
                                          (divisor 1: once per quad)
  atlas texture (new glyphs only)   --->  sampler u_atlas
  uniforms: cell size, viewport,    --->  for instance i, vertex v:
            cols, cursor index              cell   = (i % cols, i / cols)
                                            corner = (v & 1, v >> 1)
                                            pixel  = origin + (cell + corner) * cell_size
                                            texel  = (slot_xy(a_slot) + corner) * cell_size
#+end_example

The vertex shader ([[file:../c_src/renderer/gl/shaders/cell.vert][cell.vert]]) needs no vertex buffer at all: it builds
each corner from =gl_VertexID= and each cell position from =gl_InstanceID=.
The only per-cell data is the cell itself.

The fragment shader ([[file:../c_src/renderer/gl/shaders/cell.frag][cell.frag]]) reads the glyph with =texelFetch=: a text
glyph's alpha is its coverage, tinted with the cell's color, and an
emoji (the =CELL_COLOR_GLYPH= bit) brings its own colors.
Because the atlas is exactly the size it's drawn at, each screen pixel maps
to one atlas texel, with no filtering or blur. The *block cursor* is the
cell whose instance index equals =u_cursor= (=-1= when a program hides it),
plus =u_cursor2= for the right half when it's on a wide character:
pass 0 paints it in the cursor color, and pass 1 draws its glyph in the
cell's background color.

The grid can change size between frames (the window was resized); the
backend grows its buffer when that happens.

** The tab bar and the halo (MVP 4)
The cell mirror has one more row than the grid: row 0 is the tab bar,
built by the core from the TABS message, so the backend draws it like any
other row. Since MVP 6 the tabs are flat: " 1 title " each, thin =│=
separators, long titles cut with =…=, the active tab a little lighter, in
bold, with an accent line in the theme's blue along its bottom (the
=CELL_ACCENT= bit; the fragment shader draws the line). Grid
row i is mirror row i + 1; the cursor and mouse rows are shifted to match,
and a click on row 0 becomes a TAB_CLICK.

The halo is the padding around the grid: while it's lit, the frame
is cleared with the halo color instead of the background. The main loop
waits with a timeout so it can turn it off.

** Damage tracking
The GPU keeps last frame's cells in its buffer, so each frame only uploads
the rows that changed since the previous one. The core tracks the range
(=dirty_first= .. =dirty_last=) as ROWS messages arrive, and the backend
uploads just that slice with =glBufferSubData=. Both passes still draw every
cell: drawing is cheap, uploading is what costs. A new grid size moves
every cell, so then everything is uploaded.

Draws are batched by vsync: =SDL_GL_SwapWindow= waits for the screen's
refresh, messages pile up meanwhile, and the next loop applies them all
before drawing once.

The shaders are compiled into the binary with C23 =#embed=, so the renderer
is a single file with nothing to find at runtime.

** Loading GL functions
On Linux you can't count on linking against OpenGL 3.3 functions directly:
the driver hands them out at runtime. The backend lists every function it
uses once, in an X-macro (=GL_FUNCS=), and loads each with
=SDL_GL_GetProcAddress=. If one is missing, it says which.

* The event loop

#+begin_example
  reader thread                       main thread
  -------------                       -----------
  loop:                               loop:
    read framed msg from stdin          SDL_WaitEvent  (sleeps until something happens)
    SDL_PushEvent(port_event, msg) -->  port_event   -> apply ROWS to the cell mirror
    on EOF: push (nullptr) ---------->  nullptr      -> quit
                                        TEXT_INPUT   -> send TEXT
                                        KEY_DOWN     -> send KEY
                                        CLOSE        -> quit (status 0)
                                        drain the rest of the queue, then
                                        draw once if anything changed
#+end_example

Reading stdin blocks, and SDL's event loop wants the main thread, so a
small reader thread turns port messages into SDL events. =SDL_PushEvent= is
safe from any thread. Only the main thread writes to stdout, so outgoing
messages never interleave.

Draws are batched: after waking up, the loop drains every queued event and
draws once. With vsync on (=SDL_GL_SetSwapInterval(1)=), it never draws more
often than the screen refreshes.

* Running it alone

#+begin_src sh
make                                     # both builds
./priv/guiltty_gl --demo        # a fixed screen, no port
./priv/guiltty_gl-dbg --demo  # same, under ASan + UBSan
#+end_src

Closing the demo window under the debug build prints nothing: no leaks, no
errors. In the test suite the debug build runs headless on SDL's offscreen
driver, with leak checks off there only (Mesa's software EGL leaks 128 bytes
from a library it has already unloaded).

* Questions

1. Why does the core never include GL headers?
2. What's in the atlas, and why build it on the CPU?
3. How does the vertex shader know where cell 85 goes?
4. How is the cursor drawn?
5. Why does the renderer need a second thread?

** Answers
:PROPERTIES:
:VISIBILITY: folded
:END:

1. So a second backend (Vulkan) can be added without touching it, and the
   GL build never needs Vulkan headers or the other way around.
2. All 95 printable ASCII glyphs as coverage values. FreeType runs on the
   CPU anyway, and a plain bitmap can go to any backend.
3. =85 % 80 = 5=, =85 / 80 = 1=: column 5, row 1. Multiplied by the cell size
   plus the padding, that's its pixel position.
4. The fragment shader swaps foreground and background for the instance
   whose index is =cursor_row * cols + cursor_col=.
5. Reading stdin blocks. The main thread must keep handling window events,
   so a reader thread blocks instead and posts each message as an SDL event.
